# Migrate Backlog

Move this project's `backlog.org` into the places design doc 017 gives its contents: task state onto the task headings, notes about a doc into that doc, notes about nothing into `docs/loose-ends/`. Then stop committing `backlog.org`.

Do this on a quiet moment on `main`, with the other developer's branches merged or about to be rebased: it touches many docs at once.

## 1. Read and Classify

Read `backlog.org` in full. Sort every piece of it into one of these, and show the user the sorted list before changing anything (`--dry-run` stops after this).

Many backlogs hold no task entries at all — in practice they become prose notes, each with a `:DESIGN:` link to the doc it is about. So for every note with a link, check it against what it links to before deciding:

 - Resolve the link: the file exists, and the heading exists (compare heading text with the `TODO`/`OPEN`/`DECIDED` keyword and tags stripped).
 - Read the linked heading's state. An `OPEN` question in the doc and a `DECIDED` one call for different rows below.
 - Check the note's specifics — `=code=` names, numbers, "4 of 10" — against the linked section. What the section lacks is what the note would lose if dropped.

| What it is | Where it goes |
|------------|---------------|
| A task entry (`*** TODO/WIP [ID]` with `:DESIGN:`) | Its heading in the doc: state, `:QUEUED:` (the date it was queued, if known, else today), `:HANDOFF:`, `:WORKED_BY:`, `:REASON:` for one under Blocked |
| Progress notes under a task entry | A `:working:` child heading under the task in the doc |
| A paragraph about one doc ("019 built [date] — …") | Compare with the doc. If the doc already says it (often in a findings section or the summary), drop it. If it says something the doc doesn't, move that into the doc's findings section and say so |
| An `OPEN` question copied from a doc (the linked heading is `OPEN`) | Drop: the doc has it, and `bin/backlog --questions` lists it. If the note carries facts the doc's question lacks, add them to the question's body, dated, first |
| A note saying something is still open, whose link points at a `DECIDED` question or at a section that isn't a question | A new `OPEN` question in that doc's Questions section, carrying the note's text. **This is the row not to miss**: `backlog.org` is the only place the question is open, so dropping the note drops the question. A question for a person keeps their name at the front of the heading ("Keya: the sign-off wording") |
| A note about where a task stands ("done up to the accounts", "4 of 10 checked", "needs 06's number") | `:HANDOFF:` on that task's heading. If the note was in the backlog's active part, also `:QUEUED:` |
| A note that belongs to no doc ("lint is red", "the stylesheet is overdue") | A loose end: `docs/loose-ends/<slug>.org`, as `/backlog:loose-end` writes them, keeping its date |
| A project-wide status summary ("Built and green: 1477 tests…") | Drop. It goes stale the day it's written, and `bin/backlog` plus the docs are the status. If it holds something true and durable, it is a loose end or belongs in the project README |
| Elisp setup, queries, quick reference | Drop. `bin/backlog` replaces the queries; the org agenda views can live in the developer's own Emacs config |
| Anything you can't place | List it for the user. Don't guess |

A task entry whose `:DESIGN:` link is broken or whose heading is missing: list it; don't create headings to hold it.

## 2. Apply

- Edit each doc. Keep every doc's edits to its task headings and findings section.
- Write the loose ends.
- Run `bin/backlog --check` and `bin/backlog`; compare the view with what was in `backlog.org`'s active section. Every WIP/queued/held task should be there.

## 3. Stop Committing It

```bash
git rm --cached backlog.org
grep -qxF 'backlog.org' .gitignore || echo 'backlog.org' >> .gitignore   # setup may have added it
```

Keep the local file if the developer likes opening it in Emacs, regenerated: `bin/backlog --org > backlog.org`. Tell them it is now a view and edits to it go nowhere.

If the project's CLAUDE.md still describes `backlog.org` as a working surface, replace its "Design Doc Workflow" section with the one `/backlog:setup` writes now (no `backlog.org` in Key Files; `bin/backlog`; loose ends; checkpoints). If setup already replaced it, leave it.

## 4. Commit

One commit, because the move is one change and splitting it would leave a state where some tasks are in neither place:

```
chore: move backlog.org into the design docs

Task state is on the task headings, N notes moved into their docs,
Q became OPEN questions that were open nowhere else, K became loose
ends, M were dropped as repeats of their doc.
backlog.org is generated by bin/backlog --org and ignored.
```

Then tell the user what to tell the other developer: pull, rebase any branch that touched `backlog.org` (resolve those conflicts by dropping the branch's `backlog.org` changes and re-applying them to the doc headings), and update the plugin.
